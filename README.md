# hyundai-motors

현대자동차그룹 차량용 앱 개발 공모전 출품용 Pleos Connect 앱입니다. 급발진, 사고, 화재, 침수 상황을 진단하거나 직접 선택하면 대처 방법을 화면과 음성으로 안내하고, 대피 경로와 주변 도움 시설을 보여 줍니다.

> 시연용 프로토타입입니다. 진단 기준은 실차로 검증되지 않았고 안전 장치를 대신하지 않습니다. 신고 버튼은 앱 안에만 기록하는 임시 기능이며 전화, 문자, 네트워크로 아무것도 보내지 않습니다. 주변 시설은 실제로 존재하지 않는 샘플 데이터입니다.

## 상황별 화면

홈의 **위급 상황 직접 선택** 버튼이나 자동 감지로 열립니다. 각 화면에는 단계별 대처 안내(그림·음성), 대피 경로, 주변 도움 시설, 임시 신고 버튼이 있습니다.

| 상황 | 자동 감지 기준 | 대피 경로 | 주변 도움 시설 |
|---|---|---|---|
| 급발진 | 브레이크를 1.5초 이상 밟았는데 속도가 5km/h 이상 상승 | 안전 정차 구역 | 경찰서, 정비소, 병원 |
| 사고 | 0.75초 안에 35km/h 이상 감속, 또는 운행 중 에어백 전개 | 안전 정차 구역 | 병원, 경찰서, 소방서, 정비소 |
| 화재 | 실내 온도 50°C 이상이면서 1분 안에 10°C 이상 상승, 또는 엔진 과열 경고 | 대피 장소 | 소방서, 병원, 정비소 |
| 침수 | 감지 불가 (물 센서 API 없음), 직접 선택만 가능 | 고지대 대피 장소 | 소방서, 경찰서, 병원 |

임계값은 `EmergencyDetector.java`, 안내 문구와 시설 구성은 `EmergencyPlan.java`에 있습니다.

## 비상상황 확인 단계

감지되거나 버튼을 누르면 바로 대처 화면으로 가지 않고, 먼저 "○○ 상황인가요?"를 화면과 음성으로 묻습니다. 자동 감지 때 음성은 "○○이(가) 의심됩니다."로 시작합니다(조사 처리는 `guidance/KoreanParticle.java`).

| 응답 | 결과 |
|---|---|
| "네", "맞아요", "도와주세요" 등 또는 **네** 버튼 | 대처 안내 화면 |
| "아니요", "괜찮아요", "취소" 등 또는 **아니요** 버튼 | 처음 화면 |
| 알아듣지 못함 | 한 번 더 질문, 그 뒤에는 버튼 대기 |
| 자동 감지 후 15초 무응답 | 대처 안내 화면 (운전자가 답하지 못하는 상황 대비) |

**정차 대기:** 급발진의 "사이드 브레이크" 단계와 화재의 "갓길 이동" 단계는 안내가 끝나도 속도가 1km/h 미만이 될 때까지 다음 단계로 넘어가지 않습니다. 기다리는 동안 "차량이 멈추면 다음 안내를 시작합니다"를 작게 표시합니다. 속도를 알 수 없으면 기다리지 않습니다. 단계 진행은 `guidance/GuidanceSequencer.java`, 기다리는 단계 표시는 `EmergencyPlan.java`에 있습니다.

**신고:** 대처 안내 화면의 큰 **SOS 신고** 버튼을 한 번 누르면 확인 팝업 없이 바로 신고합니다. 마지막 안내가 끝나면 "신고가 필요하면 '신고해 줘'라고 말씀하시거나 신고 버튼을 누르세요."라고 말한 뒤에 음성 인식을 시작합니다. "신고해 줘", "119", "112", "도와줘", "불러 줘" 등을 신고 요청으로 봅니다(`guidance/ReportIntentClassifier.java`). 신고는 `MockEmergencyReporter`에 기록만 하고 아무 데도 보내지 않습니다. 화면에는 접수 결과와 전달한 정보(위치, 상황, 시각, 차량 속도 기록)를 보여 줍니다. 흐름은 `report/ReportFlow.java`에 있습니다.

**대피·출동 현황:** 신고 음성이 끝나면 바로 이 화면으로 넘어갑니다. 대피 장소(이름·거리·방향·경로 안내), 112·119가 보낸 경찰서·소방서·병원의 예상 도착 카운트다운(신고 순간부터 1초 단위), 내 위치를 가운데 둔 미니 맵(앱이 직접 그림, 외부 지도 없음)을 보여 줍니다. 도착 시간은 `ResponseEstimator`, 화면은 `EvacuationStatusOverlay.java`와 `ResponseMapView.java`에 있습니다.

자동 감지된 급발진·화재가 5초 이상 정상으로 돌아오면 처음 화면으로 돌아갑니다. 사고는 차가 멈춘 것이 정상이라는 뜻이 아니므로 자동으로 닫히지 않습니다. 음성 인식은 Pleos SpeechToText를 먼저 쓰고, 실패하면 Android 음성 인식을 쓰고, 둘 다 없으면 버튼만 표시합니다. 답변 해석은 `AnswerClassifier.java`에 있습니다.

표에 있는 엔진 출력 차단, 자동 긴급 제동, 화면 녹화는 Pleos SDK에 차량 제어·녹화 API가 없어 구현하지 않았습니다.

## 출동 기관과 예상 도착 시간

위급 화면에서 소방서, 경찰서, 병원(구급차), 도로공사(순찰·긴급견인), 정비소(견인)를 **예상 도착 시간이 빠른 순**으로 보여 줍니다. 각 카드의 **임시 출동 요청**을 누르면 앱에만 기록되고, 도착까지 남은 시간이 1초 단위로 줄어듭니다.

예상 시간은 `출동 준비 시간 + (직선 거리 × 1.3) ÷ 평균 속도`로 계산합니다(`ResponseEstimator.java`).

| 기관 | 준비 시간 | 평균 속도 |
|---|---|---|
| 소방서 | 1분 | 40km/h |
| 경찰서 | 1분 | 45km/h |
| 병원(구급차) | 1분 30초 | 40km/h |
| 도로공사 | 5분 | 50km/h |
| 정비소(견인차) | 10분 | 35km/h |

이 값은 시연용 가정입니다. 실제 교통 상황과 도로 경로는 반영하지 않으며, 시설도 샘플 데이터입니다.

## 졸음운전 안내 (부가 기능)

| 상황 | 기준 | 안내 |
|---|---|---|
| 같은 방향 단조 주행 | 시속 60km 이상, 진행 방향 변화 10° 이내로 15분 | 환기와 주의 안내 |
| 장시간 운전 | 연속 2시간 (10분 이상 정차하면 다시 계산) | 휴게소·졸음쉼터 휴식 권고 |

음성과 홈 화면의 작은 알림으로만 안내하고, 한 번 안내하면 15분 동안 반복하지 않습니다. 비상상황 화면이 떠 있을 때는 동작하지 않습니다. 기준은 `DrowsinessMonitor.java`에 있으며, 진단 테스트 탭에서 20초짜리 시연을 할 수 있습니다.

## 시연 방법

- **직접 선택:** 홈의 급발진·사고·화재·침수 버튼
- **자동 감지 재현:** **진단 테스트** 탭의 시나리오 버튼 (시연용 데이터 사용)

실제 차량에서 위급 상황을 유도하지 마세요.

### PC 에뮬레이터 시연 설정

PC 에뮬레이터의 내비게이션 앱은 지도를 불러오지 못합니다. 그래서 **진단 테스트** 탭 맨 위에 **시연 설정**을 두었습니다. 경로·위치 설정은 처음에는 켜져 있고, 영상 모드는 꺼져 있습니다.

- **경로 안내를 앱 안에서 시연:** 시설의 **경로** 버튼을 누르면 앱 안에서 시연용 지도가 열립니다. 내비게이션 앱은 실행되지 않습니다.
  - 시설의 거리와 방향으로 바둑판 모양의 가상 경로를 만듭니다. 실제 도로는 아닙니다.
  - 시속 40km 기준으로 10배속 재생합니다.
  - 회전 150m 전과 도착할 때 음성으로 안내합니다.
  - 일시정지, 처음부터, 닫기 버튼이 있습니다.
  - 끄면 원래대로 Pleos 내비게이션에 경로를 보냅니다.
- **Pleos 내비게이션 경로 (`facility/RouteNavigator.java`):** NaviHelper `requestRoute` 전에 `cancelRoute`로 이전 목적지를 지우고, 장소 이름과 주소를 함께 보냅니다. 경로 시작·안내 중·취소·도착·오류(`NaviErrorCode`)를 화면 문구로 보여 주고, 안내 중에는 `getTBTInfo`로 "다음 안내: 300m 앞 우회전"을 작게 표시합니다. Logcat 태그는 `RouteNavigator`입니다.
- **시연 위치 사용:** GPS 대신 서울 강남의 샘플 위치를 기준으로 주변 시설과 거리를 계산합니다.
- **영상 모드 (시연 영상 촬영용):** 켜면 진단 테스트 탭과 테스트 문구를 숨기고, 위치는 에뮬레이터 Location(FusedLocation) 값을 씁니다. 앱 제목을 길게 누르면 촬영 메뉴(시나리오, 리드인, 확인 질문 건너뛰기, 음성 신고 연출, 영상 모드 끄기)가 열립니다. 음성 신고 연출을 켜면 신고 대기 중에 화면을 두 번 탭할 때 "신고해 줘"를 인식한 것처럼 보여 줍니다. 영상 모드에서 경로 안내는 항상 NaviHelper로 요청하고, 메뉴에서 대피 장소 자동 경로 안내(신고 후 / 상황 확인 직후)와 대체 경로 화면(내비 지도가 안 뜰 때 앱 안 경로 화면을 함께 띄움, 경찰서·소방서 핀 포함)을 고를 수 있습니다. 설정값은 `demo/VideoConfig.java`에 있습니다. 영상 모드에서는 샘플 시설 대신 `VideoConfig`의 실제 장소(이름·위도·경도)를 쓰고, 거리는 하버사인 공식, 방향은 방위각으로 현재 SDK 위치에서 계산합니다(`facility/GeoMath.java`). 값이 비어 있는 장소는 "장소 미설정"으로 표시합니다. 안전 정차 장소는 시나리오마다 다릅니다(급발진·충돌: 양재역 공영주차장, 차량 화재: 매헌윤봉길의사기념관 주차장(지상)). 화재 차량은 실내·지하 주차장으로 안내하지 않습니다. 영상 모드 화면에서는 "대피 장소"를 "안전 정차 장소"로 표시합니다.

코드: `demo/DemoRoute.java`(경로 생성), `demo/RouteMapView.java`(지도 그리기), `demo/RouteDemoOverlay.java`(재생과 안내)

### 단계별 반복 애니메이션

대처 안내의 각 단계 그림이 행동을 따라 짧게 반복해서 움직입니다. 예를 들어 브레이크는 눌렀다 떼고, 비상등은 깜빡이고, 대피는 멀어지고, 고지대 대피는 위로 올라갑니다. 단계와 동작의 짝은 `EmergencyPlan.java`, 동작 구현은 `StepAnimator.java`에 있습니다.

Pleos 가이드의 "운전 중 애니메이션으로 시선을 유도하지 않는다" 원칙에 따라 **정차 중에만** 움직입니다. 주행 중, 화면이 보이지 않을 때, 시스템에서 애니메이션을 끈 경우에는 그림이 멈춰 있습니다.

## 레이아웃 구조

| 창 크기 | 구성 |
|---|---|
| 폭 840dp 미만 | 한 열, 하단 내비게이션 |
| 폭 840dp 이상 | 왼쪽 내비게이션 + 핵심/상세 두 패널 |
| 주행 중 | 상세 패널을 숨기고 핵심 정보와 주요 동작만 표시 |

앱 창은 Pleos Connect에서 이동·크기 변경이 가능해서, 기기 방향이 아니라 **창 크기**를 기준으로 화면을 나눕니다.
미리보기는 [docs/layout](docs/layout)에 있습니다.

## 파일 위치

| 경로 | 내용 |
|---|---|
| `MainActivity.java`, `EmergencyOverlay.java` | 화면 표시 |
| `MainViewModel.java` | 진단, 안내 재생, 상태 유지 |
| `telemetry/` | 실제 차량 데이터와 시연 시나리오 |
| `diagnosis/` | 진단 규칙과 대처 단계 |
| `guidance/` | 음성 안내 |
| `facility/` | 샘플 시설과 경로 요청 |
| `report/` | 모의 신고 |
| `data/` | 주행 상태 인터페이스와 임시 구현 |
| `res/layout/` | 좁은 창 레이아웃 |
| `res/layout-w840dp/` | 넓은 창 레이아웃 |
| `res/values/themes.xml`, `colors.xml`, `dimens.xml` | 색상, 글자 크기, 터치 영역 |
| `res/values/strings.xml` | 화면 문구 |

## 임시로 둔 부분

- 주행 상태는 화면의 전환 버튼으로 바꿉니다. 제출 전에 `CarUxRestrictionsManager` 구현으로 교체하고 버튼을 지워야 합니다.
- `SampleFacilityRepository`의 시설은 가상 데이터입니다. 실제 장소 검색 API로 교체해야 합니다.
- `MockEmergencyReporter`는 기록만 합니다. 실제 신고 연동은 구현하지 않았고, 전화·문자 코드가 들어가면 `ManifestSafetyTest`가 실패합니다.
- 대처 문구는 일반 안내입니다. 대상 차량 취급설명서와 전문가 검토가 필요합니다.
- 진단은 앱이 실행 중일 때만 동작합니다.
- 색상과 크기는 Pleos 공식 디자인 토큰이 아닙니다.
